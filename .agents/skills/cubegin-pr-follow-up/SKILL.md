# PR 跟进

创建 PR 或向其推送后，安排一个子代理跟进，提供 PR 链接、分支、提交 SHA 和按
[CI 规则](../../../docs/ci.md)预期触发的检查。主代理继续开发。同一个 PR 只需一个跟进代理，
推送新提交后更新跟进目标。

1. 确认 PR 最新提交，跟踪对应的 CI 和审查讨论。检查未出现时先核对路径规则，若应触发则排查原因。
2. 查看失败日志。确认是临时 runner 故障时，在同一提交上重试。可复现的问题与主代理协调修复，并在本地验证。
3. 对照当前差异检查未解决的讨论。修复有效问题，等修复出现在 PR 后标记为 Resolved。已有修复或经核实不再适用的讨论也应关闭。仍有分歧或未解决的问题保留并报告。
4. 主代理管理活动工作树、提交和推送。子代理可在明确分工后独立准备修复。推送后重新核对新提交，交付或获准合入前报告提交 SHA、检查结果、已关闭讨论和阻塞项。

子代理不可用时由主代理跟进。提交、推送和合入沿用任务已有的授权范围。
