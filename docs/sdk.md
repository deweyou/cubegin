# SDK examples

All event/type IDs are exposed by the catalog. State records retain puzzle-specific
layouts. Only the original 3x3 API uses a single URFDLB facelet string.
For artifact builds and local product dependencies, see the
[README integration guide](../README.md#build-artifacts-and-consume-them-in-products)
or [Chinese guide](../README_ZH.md#构建产物与产品接入).

```ts
import {createWorkerClient} from 'cubegin/worker';
const client = createWorkerClient();
const api = client.engine;
const scramble = await api.generateEvent('fto', 42);
const solvedBy = await api.solveEvent('fto', scramble.algorithm);
const image = await api.evaluateEvent('fto', scramble.algorithm);
// image.svg is an SVG net; image.state is the puzzle-specific state record.
const cases = await api.trainingCases('333.pll');
const training = await api.generateTraining('333.pll', 42, {
  enabled_case_ids: [cases[0].id], natural: true,
  orientation: {bottomColor: 'white', frontColor: 'green'},
});
const batch = await api.generateBatch('333', 42, 5);
const assist = await api.solveAssist('333', ['cross', 'eoline'], 'R U F', {
  max_depth: 12,
});
const timeline = await api.playerTimeline('sq1', '(1,0) /');
const halfway = await api.playerSvg('sq1', '(1,0) /', 1, 0.5);
const geometry = await api.playerFrame('sq1', '(1,0) /', 1, 0.5);
// Insert SVG in a trusted view, or render geometry with the product GPU backend.
client.dispose();
```

`playerTimeline` returns `schemaVersion: 1`, initial piece geometry and operations.
`playerFrame`/`playerSvg` take completed move count plus progress through the next
move (0..1). The final position is `(steps.length, 0)`. Invalid positions fail.
The net is a schematic view; the player SVG is an orthographic 3D projection.
Colors and camera currently follow the legacy defaults.

```swift
import Cubegin
// Call CPU-bound work on an application-owned background executor.
let s = try generateEvent(event: "pyram", seed: 42)
let result = try evaluateEvent(event: "pyram", algorithm: s.algorithm)
let solution = try solveEvent(event: "pyram", algorithm: s.algorithm)
let trainingJSON = try generateTraining(id: "333.pll", seed: 42, optionsJson: "{}")
let frameSVG = try playerSvg(event: "sq1", algorithm: "(1,0) /", completed: 1, progress: 0.5)
```

```kotlin
import io.github.deweyou.cubegin.*
// Schedule on an application-owned worker/dispatcher.
val s = generateEvent("pyram", 42u)
val result = evaluateEvent("pyram", s.algorithm)
val solution = solveEvent("pyram", s.algorithm)
val trainingJson = generateTraining("333.pll", 42u, "{}")
val frameSvg = playerSvg("sq1", "(1,0) /", 1u, 0.5)
```

Native event records expose `stateJson`; variable-topology training/assist/player
results use JSON strings. Swift/Kotlin names are generated by UniFFI. Swift sources
live with the package; Kotlin bindings ship in the AAR. Options use the same JSON
keys as the Web API. `solveAssist` takes a
JSON array of method names. All failures cross bindings as explicit errors.

Full solving is available for 2x2/3x3/4x4/Pyraminx/Skewb/Square-1/FTO. Clock uses
inverse notation. Large cubes and Megaminx expose state, generation and rendering;
requesting an unavailable full solver fails. Multi-blind uses `generateMultiBlind`
with an explicit cube count. API and seeded output stability are release-scoped.

The CLI exposes `events`, `types`, `cases`, `event-evaluate`, `event-scramble`,
`event-solve`, `event-inverse`, `event-timeline`, `training`, `batch`, `multiblind`,
`assist`, `player`, `player-svg`, `fmc`, plus original 3x3 commands. `--help` lists
the arguments. Use quoted
algorithms as a single argument. `training`/`assist` accept an optional JSON options
argument. CLI binaries are currently built with Cargo, not distributed as installers.
